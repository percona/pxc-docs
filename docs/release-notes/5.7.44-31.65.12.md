# Percona XtraDB Cluster 5.7.44-31.65.12 (2026-07-20)

This release is part of {{post}}. The fixes are available to [MySQL 5.7 Post-EOL Support from Percona customers](https://www.percona.com/post-mysql-5-7-eol-support).

This release includes fixes from [Percona Server for MySQL 5.7.44-58](https://docs.percona.com/percona-server/5.7/release-notes/5.7.44-58.html) and [Percona Server for MySQL 5.7.44-59](https://docs.percona.com/percona-server/5.7/release-notes/5.7.44-59.html).

## Release information

The fixes ported to 5.7 are the following:

[`Bug#38712932`](https://github.com/mysql/mysql-server/commit/1c7b3e6e): Group Replication applier pipeline validations.

[`Bug#38673285`](https://github.com/mysql/mysql-server/commit/29f48df9): Group Replication snapshot decode validations.

[`Bug#39040226`](https://github.com/mysql/mysql-server/commit/19ac235c84f): FTS index construction ignores memory limits.

[`Bug#35634700`](https://github.com/mysql/mysql-server/commit/8d1aad6b5a7): Assertion failed in `sql_planner`: `bool Optimize_table_order::greedy_search()`.

[`Bug#38928287`](https://github.com/mysql/mysql-server/commit/3c5baa98cdc): Crash inside of the query parser/planner/resolver.

[`PS-10953`](https://perconadev.atlassian.net/browse/PS-10953): Prevents a server hang when a large query is killed during parsing.

[`PS-10953`](https://perconadev.atlassian.net/browse/PS-10953): Fixes a memory leak during shutdown when replaying spatial-index MBR updates during recovery.

Fixes a regression introduced by these commits for both spatial indexes and Varchars.

[`Bug#25579578`](https://github.com/mysql/mysql-server/commit/a87a5dbb2a46c5f9bd974999a3fc2cb0460877fe): INNODB: FAILING ASSERTION: !FIELD->PREFIX_LEN || FIELD->FIXED_LEN == FIELD->PREF

[`Bug#39129182`](https://github.com/mysql/mysql-server/commit/845d525d49c8027a4d0cdcc43372c96ba295c857): Mysqld Crash due to "Deadlock Detected!" Error

[`Bug#39116965`](https://github.com/mysql/mysql-server/commit/413d194f6498bce5da807d77ec5dea097adbc4db): During connection setup, connection attribute parsing could read a length-encoded size field before verifying that the complete field was present in the packet, leading to an out-of-bounds read. A size check is now performed before reading the field.
